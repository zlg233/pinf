## 原件与产物分开

- `raw/` 原件只读使用，清洗不覆盖原文，也不在原文件里补来源或审核状态。
- 每个文件用 SHA256 识别内容，原始压缩包保留，解压后的 13 份文件均已重新读取并校验。
- 以后新增一批资料，使用新的批次目录；不要覆盖此批文件。文档版本和审核记录通过清单关联。
- 小程序原型和功能架构属于产品参考材料，与医学参考候选文件在清单上分开，不进入护理问答语料。
- 汇编语料先保留为待溯源资料，不能因为文件名有“终版”就当作已审核来源。
- 原件、压缩包和未来生成的处理产物已由本目录 `.gitignore` 排除。清单、说明和方案可以纳入版本管理；原件需要单独备份，Git 不提供这部分备份。

以后新建归档的压缩包副本放在 `archives/`，待处理投递文件放在 `inbox/`，避免反复扫描旧归档。本批最初的ZIP副本仍保留在上表位置，并按导入记录识别跳过。后续正式部署时可将整个资料根目录迁移至服务器持久化目录，通过配置指定，保持相对路径不变；不要放进 PostgreSQL 的 `PGDATA` 数据目录。

## 你以后怎样添加资料

1. 把新ZIP、PDF、DOCX放进本目录的 `inbox/`。ZIP里可以保留中文目录；旧DOC会登记，但暂不自动转换。
2. 在 `D:\BK\AIProjects\pinf\test\rag-pilot` 运行：

```powershell
.venv/Scripts/python.exe -X utf8 ingestion.py run
```

3. 查看 `indexes/CURRENT.json` 里 `report` 对应的Markdown报告；它列出成功、部分处理、阻断、排除和失败。相同文件及相同处理参数会复用向量。
4. 通过n8n运行时，由同一HTTP任务入口执行上述流程；先按 `DEPLOYMENT.md` 配置服务和凭据，再手动执行模板。定时触发只有在你启用工作流后才生效。

这里的“自动清洗”是结构与格式处理：保存原文、清理空白和重复页边信息、检测问题页；不会让生成模型重写医学建议。两栏读序不确定、表格、图片、流程图等会进入问题清单，原页不会被当作已可靠解析的普通段落。

## 状态怎么理解

| 状态 | 含义 |
| --- | --- |
| `indexed_pending` | 当前可处理内容已生成向量，仍需审核 |
| `partial_pending` | 部分内容生成向量，另有被跳过的页面/表格/图片或溯源事项 |
| `blocked_quality` | 当前没有内容通过提取条件，暂未产生向量 |
| `excluded_product` | 产品参考资料已归档，未进入医学索引 |
| `failed` | 本文件处理报错；同批其他文件继续处理 |

删除 `inbox` 文件不会自动撤回已经归档的知识。更新同名投递文件会生成新版本，并在下一次快照中替换旧版本；不同文件名或不同格式的同源医学资料需人工确认归并。本阶段不提供临床审核批准、正式发布或自动撤回接口。

内部查看检索原文：

```powershell
.venv/Scripts/python.exe -X utf8 ingestion.py query --question '早产儿出院后如何随访？' --allow-pending
```

去掉 `--allow-pending` 将使用正式可见性过滤，当前返回零条。这条命令只返回原文检索片段，不是已经接入小程序的医学回答。
