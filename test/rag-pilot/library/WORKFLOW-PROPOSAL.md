# 自动资料清洗与知识库入库草案

日期：2026-10-24。用户要求继续后，按推荐方案 B 实施了本地阶段。当前结果见 `REPORT.md`；n8n 为待配置导入模板，生产部署、正式审核发布及 pgvector 导入尚未执行。

## 目标与现状

用户希望后续只需放入新的知识文件，即可自动整理、清洗、分段、生成向量并更新知识库，并逐步接入现有 n8n AI 问答。

现有后端将问答请求转发给 n8n，项目部署包含 PostgreSQL/pgvector，但代码中尚未发现 RAG 文档/片段业务模型。上一轮 `pilot.py` 已具备本地 ONNX 向量化、分词长度控制、SQLite 索引和审核过滤，应该复用。不过其 PDF 提取器仅针对旧公报指定页码与栏位，不能直接套用到本批任意 PDF。原来的 chunk ID 也没有显式包含文档身份，多文档流程需要补充，避免不同文件互相覆盖。

最初盘点完成了 13 份原件归档和校验：10 份医学参考候选、1 份汇编语料、2 份产品参考。以下保留实施前设计；具体已完成范围与质量阻断以验收报告为准。原来的 170 片段试验索引独立保存。

## 可选方案

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A：仅本地 Python | 扫描目录，一条命令清洗、向量化、写本地索引和报告 | 最快验证；后续需补服务接口才能交给 n8n 调用 |
| B：Python 处理，n8n 编排（建议） | 同一套 Python 流程既提供本地命令，也提供内部任务接口；n8n 负责触发、轮询和分支处理 | 复用现有模型与代码，解析可独立测试，n8n 流程较简单；需要部署独立处理服务 |
| C：全部放在 n8n 节点 | 节点负责解析、分段、Embedding、向量库写入 | 文本材料可快速搭建，但本批乱码、双栏、DOC、表格处理更难维护，模型兼容性也需另行验证 |

采用 B 的本地阶段：Python负责内容处理，n8n负责触发和查看状态。

## 数据路径与流程

```text
投递 ZIP / PDF / DOCX
  → 安全解包、登记 SHA256 与版本
  → 判断用途、是否已处理、是否支持该格式
  → 结构化提取正文与定位信息
  → 清洗及质量检查
       ├─ 乱码、扫描页、复杂表格/流程图、旧 DOC → 异常清单
       ├─ 产品材料 → 仅归档
       └─ 可处理 → 分段、场景元数据、父段落
  → 本地 Embedding（复用当前固定版本模型）
  → 写入待审核索引与报告
  → 护理团队确认来源、适用范围及内容
  → 发布 approved 版本 → 正式问答检索
```

自动化负责资料处理，不把“清洗成功”视为“医学审核通过”。待审核材料可在明确的内部测试模式检索；默认正式检索只读取已发布且通过审核的版本。审核可以在片段/章节层面进行，复杂页不能随整份文档直接放行。

## 第一阶段交付范围

1. 在 `test/rag-pilot/` 内开发独立的批量处理入口，复用 `LocalEmbedder`、分词计数与已有检索能力；现有业务文件保持不变。
2. 支持可提取文字的 PDF、DOCX，保留章节、PDF 页码或 DOCX 段落/表格定位。清理重复页眉页脚、异常空白，不凭空改写医学句子；数字、剂量、否定词、单位、条件与表格行列关系不能因清洗丢失。旧 DOC、图片和流程图先返回明确的待处理原因，不伪装成功。
3. 双栏与表格需要版面识别或明确解析配置；读序不确定、字符映射异常时进入质量阻断。扫描/OCR 和旧 DOC 转换作为独立可选适配器，第一阶段不承诺所有资料都能自动通过。
4. 为本批资料生成单独的清洗产物、片段、SQLite/NumPy 本地待审核索引及可读报告。SQLite 是本地验证后端，不宣称已写服务器 pgvector。仅生成已选入处理范围且质量通过的资料向量。
5. 为同一流程提供独立内部 HTTP 任务服务，并提供默认停用、无凭据的 n8n 工作流导入 JSON：手动触发/定时触发 → 提交任务 → 等待/查询状态 → 成功摘要或异常分支。首先本地验证 JSON 结构与服务接口；未在用户 n8n 实例导入执行前，不能称为 n8n 联调成功。定时节点的时区与周期显式配置，不自动启动线上定时任务。
6. 单独编写 PostgreSQL/pgvector 迁移与接入说明，待本地验收后再实施服务器导入和问答接入。第一阶段不更改生产表、生产 Compose 或现有 AI 工作流。

## 核心实现约束

- **去重与版本**：内容哈希 + 解析版本 + 分段参数 + 模型版本构成处理指纹。重复运行不新增同版本数据；正文或参数变化生成新版本，避免陈旧片段残留。
- **片段身份**：片段键包含文档内容哈希、提取版本与定位信息；保留原始文件路径、原文标题、章节、父段落和来源关系。
- **同源资料**：字节去重自动进行；不同格式但同一文件家族的内容只提出重复候选，人工确认 canonical source 后再决定是否发布。不得直接按标题删除。
- **模型隔离**：继续使用现有固定版本的 384 维多语言 ONNX 模型；查询使用同一个向量模型。未来换模型必须独立重建索引，不能只凭维度相同就混用。
- **场景隔离**：区分早产儿/其他人群，住院/出院/居家/随访；产科早产防治材料不能自动视为婴儿居家护理。无法确认场景的内容保留 unknown 并等待审核。
- **任务可靠性**：先写暂存产物再原子发布当前版本，单文件失败隔离；固定资料根目录、互斥锁和运行 ID，拒绝任意系统路径、并发重复任务与清洗过程中发布半成品。报告记录成功、跳过、失败、异常与片段数。
- **HTTP 范围**：仅绑定本地或容器内网；认证令牌从环境变量注入。请求使用登记批次 ID，不接收任意 shell 命令或系统文件路径；提交返回任务 ID，查询接口用于轮询。凭据不写入 workflow JSON 或日志。
- **不执行文档指令**：附件内容只作为原文数据；不按其中的链接自动执行程序，也不让文档内容更改审核状态或工作流配置。

## 验收与 TDD

先写会失败的测试再实现：安全解包和中文文件名；13 份原件完整性；产品文件排除；乱码/扫描页/DOC 分支；DOCX 表格与定位；数字、单位和否定词保留；不超模型 token 上限；重复运行计数不变；跨文档 ID 不冲突；内容更新后旧版本不可见；单文件失败与任务锁；pending 不进入正式检索；HTTP 认证、提交/轮询、错误返回；n8n JSON 不包含密钥且默认停用。

真实模型测试另记录实际片段数量、耗时与检索样例，不以模拟向量代替真实 Embedding。保留上一轮已发现的回答遗漏与场景混用问题，本次自动入库不等于已解决生成质量问题。

## 后续生产接入

资料根目录通过配置迁移至服务器独立持久化目录，原件只读挂载给处理服务，清洗产物单独可写，不能写入 `PGDATA`。由处理服务负责读原件，n8n 通过内网 HTTP 调用，避免在 n8n 容器里临时安装 Python/模型或依赖 shell 执行。

生产阶段增加独立文档、版本、片段和向量表及审核发布流程。若纳入 Flask 模型，按仓库约定同步 model、db_migrations、to_dict；不复用聊天记忆表存文档向量。向量类型/维度及 SQL 查询与本地模型一致。先验证服务器 pgvector 版本与 n8n 实际版本，再选择并测试检索接入方式。
