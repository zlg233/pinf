# 知识库片段审核操作指引（护理团队）

目标：把 AI 预审过的片段，由**真实审核人**确认后变成 `approved`，进入正式问答检索。
AI 的判定只是建议，不会自动生效；`apply_review.py` 会拒绝把"AI 预审"当作审核人。

## 一、拿到什么

一份 Excel：`prescreen-suggestions-*.xlsx`（当前 1512 行）。

| 列 | 说明 |
|---|---|
| 序号 / 片段ID（勿改） | 定位用，**不要修改** |
| 文档 / 原文位置 | 出处，`md:12` 表示 Markdown 第 12 段 |
| 片段文本 | 要审的内容 |
| 预审建议 / 预审理由 / 风险标记 | AI 的参考意见 |
| **判定** | 空着，**由你选**：通过 / 驳回 / 待修改 / 待补充原文 |
| 适用人群 / 护理场景 | 已按建议预填，可改 |
| 修改建议 / 审核人 / 审核日期 | 你填 |

## 二、审核分三类做，不要逐条从头翻

### 第 1 类：整批驳回（约占 35%）

用「风险标记」或「预审建议 = 驳回」筛选，整批确认即可。典型内容：

- 参考文献条目、作者单位、执笔/专家名单、利益冲突声明
- 页眉页脚、页码、刊名卷期、DOI、扫码提示
- 章节标题单独成行、表题（"表 3 …"）
- 公文外壳、行政职责条款（如"各级卫生计生委负责…"）

**表格结构性碎片**（表题、`|---|` 分隔行、空单元格行、只有表头没有数据）→ 也整批驳回。

### 第 2 类：核数（约占 45%，最花时间）

筛选 `风险标记` 含 `needs_original_check` 的行。这些片段本身句子通顺，**但含数字**，必须回原文核对后再判：

| 要核什么 | 例子 |
|---|---|
| 剂量 | 维生素 D 800～1000 IU/d、铁 2 mg/(kg·d)、palivizumab 15 mg/kg |
| 孕周/月龄阈值 | 胎龄＜32 周、校正月龄 3 月、<8 月龄 |
| 百分位 | 第 25 百分位、P₂₅～P₅₀ |
| 频次与时长 | 1 次/月、最多 5 剂、随访至 3 岁、隔离 24 小时 |
| 推荐等级 | ⅠA、ⅡB、ⅢC |
| 禁忌与安全 | 任何"禁忌、暂缓、暂停、不宜、避免"的判断 |

**核对的数一致 → 通过；不一致或原文也查不到 → 驳回。**

### 第 3 类：确认可用（约占 18%）

筛选 `预审建议 = 通过` 且无风险标记的行，通读一遍，语句完整、说得通即可通过。

## 三、判四个值的含义

| 判定 | 什么时候用 |
|---|---|
| 通过 | 内容正确、可独立理解、条件齐备；含数字的**已核对过** |
| 驳回 | 内容错误/过时/与原文不符/与知识库无关，不值得改 |
| 待修改 | 方向可用但缺主语、缺条件、半句话；请在"修改建议"写清怎么改 |
| 待补充原文 | 明显截断或只剩表格碎片，需要重新转换原文 |

拿不准的一律不要选「通过」。

## 四、必须填的两列

- **审核人**：真实姓名（不能填"AI""预审""机器"之类，否则回填脚本会报错）
- **审核日期**：`YYYY-MM-DD`

## 五、建议顺序（按性价比）

1. 「预审建议 = 通过」的 267 条 —— 最快，先跑通流程
2. 「预审建议 = 驳回」的 524 条 —— 整批确认，5 分钟
3. `needs_original_check` 的 467 条 —— 按文档分批核数，最耗时
4. 其余「待修改」「待补充原文」—— 视情况改或驳回

## 六、填完之后

1. 保存为同一个 xlsx 回传（不要改名、不要增删行、不要改"片段ID"列）。
2. 技术侧执行：

```bash
cd test/rag-pilot
.venv/Scripts/python.exe -X utf8 apply_review.py --input <回传的xlsx> --dry-run   # 先校验
.venv/Scripts/python.exe -X utf8 apply_review.py --input <回传的xlsx>            # 生成 approved 快照
```

3. 脚本会在以下情况**拒绝生成**：
   - 一个"通过"都没有（防止空知识库上线）
   - 有行判定非法、片段ID不存在、缺审核人、日期格式错、行重复
   - 通过项缺"适用人群"或"护理场景"

4. 通过后产出：`decisions-*.json`（审计留痕）+ `indexes/approved-*/vectors.sqlite`（只含通过项）。
