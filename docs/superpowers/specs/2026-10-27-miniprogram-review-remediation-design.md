# 萌芽护航小程序审核问题修复方案

日期：2026-10-27

状态：修复一（协议与授权）已实施；修复二（视频）最终采用「后端开关隐藏」并已实施。

## 审核驳回原文（本次提审结果）

- 审核失败原因 1：存在平台未允许的服务内容，违反《微信小程序平台运营规范常见拒绝情形 3.4》。详情：登录环节涉及收集、使用和存储用户信息，需补充《用户服务协议》及《隐私政策》，明确告知使用目的、方式和用途，并在取得用户授权同意后再获取信息。
- 审核失败原因 2：存在个人主体小程序未开放的服务类目，违反《常见拒绝情形 2.1》。详情：小程序涉及视频服务，属个人主体未开放类目，建议申请企业主体小程序。

## 更新与决策记录

- 2026-10-27 初版：按「移除小程序内视频、改为公众号文章入口」设计。
- 2026-10-27 调整一：用户选择保留视频栏目、手动维护公众号发表链接，第二项改由 `2026-10-27-manual-official-video-cards-design.md` 承接。
- 2026-10-27 调整二（最终）：用户决定**保留小程序内视频播放与现有 updatedb 素材链路**，不修改播放与链接解析逻辑，改为**后端开关隐藏视频入口**。因此公众号卡片方案暂停，本文修复二改为开关方案。

## 目标和已确认信息

- 小程序对外名称：萌芽护航。代码内产品名已统一为「萌芽护航」（2026-10-27 用户确认）。
- 运营者对外名称：萌芽护航团队。此称谓不代表已核验平台登记主体；提审前应与后台登记信息核对。
- 隐私联系邮箱：23klin@stu.edu.cn。
- 本次提审目标是让上述两项驳回点在审核员可见范围内不再成立。

## 采用的路径及替代方案

1. **（最终采用）协议 + 后端开关隐藏视频入口**：补齐协议与同意门禁；视频能力保留在小程序内，由后端开关决定入口是否出现。优点是改动小、可随时恢复；代价是提审代码包里仍保留播放能力（风险见下）。
2. 协议 + 彻底移除播放器/页面注册/播放请求：过审最稳，但视频功能需在审核通过后重做。
3. 协议 + 公众号文章入口（`wx.openOfficialAccountArticle`）：不依赖小程序内播放能力，但需要每条内容有真实已发表文章链接，且平台是否认可仍无保证。

用户选择路径 1，并已知悉其风险。

## 修复一：协议与授权（已实施）

要求：

1. 新增并注册《用户服务协议》《隐私政策》原生页面，无需登录、无需同意即可阅读；启动时的认证跳转不得阻断这两个页面。
2. 登录页保留默认未勾选的同意框，覆盖验证码发送、验证码登录、密码登录、微信登录及手机号授权。用户未同意时既不调用对应后台接口，也不触发手机号授权组件。
3. 对实际使用的微信隐私接口，接入微信官方隐私授权流程。
4. 在「我的」提供两个协议的长期入口。
5. 协议依据实际实现描述信息收集目的与方式；不编造主体资质、保存期限、服务器所在地或安全承诺。
6. 微信后台《小程序用户隐私保护指引》由账号管理员填写，属平台配置，不视为代码完成。

实施落地：

- 协议正文单一数据源 `wx_end/src/domain/legal/documents.ts`（用户服务协议 9 章、隐私政策 8 章），运营者与联系邮箱为常量。
- 页面 `wx_end/src/pages/terms`、`wx_end/src/pages/privacy`，共用 `wx_end/src/components/legal/LegalDocumentView.tsx`。
- 未登录可读：`wx_end/src/domain/legal/public-pages.ts` 列出放行路由，`wx_end/src/app.tsx` 按当前页与冷启动路径双重判断跳过认证跳转。
- 同意门禁：`wx_end/src/domain/legal/consent.ts` 统一文案，登录页「获取验证码」「验证码/密码登录」「微信登录」共用；未勾选时不渲染 `openType="getPhoneNumber"` 的按钮，因此不会拉起手机号授权组件。
- 「我的」页新增两个协议入口。

未做：未接入 `wx.requirePrivacyAuthorize` 主动弹窗。理由是微信在调用手机号授权时会按后台配置的隐私保护指引自动弹出官方隐私弹窗；在后台指引未配置时主动调用存在阻断正常登录的风险，需等后台配置完成后另行评估。

## 修复二：视频（最终采用：后端开关隐藏）

决定：保留小程序内播放（`/content/videos`、`?include_play_url=1`、`<Video>` 与 updatedb 素材同步链路均不改动），只由后端开关控制入口可见性。

实现要求：

1. 复用现有开关 `FEATURE_CLASSROOM_VIDEO`（`backend/config.py` → `GET /api/settings/features` → `wx_end/src/store/features.ts`），不新增开关。
2. **fail-closed**：前端默认值为关闭；只有开关已从后端加载完成且明确返回 `true` 时才显示视频入口。请求失败、超时、响应缺字段一律视为关闭。
3. **详情页拦截**：视频详情页不依赖入口是否可见，开关未加载或关闭时不请求播放地址、不渲染播放器，直接提示「视频内容暂未开放」。拦截必须位于所有 Hook 之后，否则反向会引起 Hook 数量变化白屏。
4. Hook 顺序：课堂页与问答页的开关跳转改为 effect，渲染期不再提前 `return null`。
5. 首页课堂入口仍由「文章或视频任一开启」控制；视频关闭时不影响文章栏目。
6. 后台视频接口、`updatedb` 同步、App 端（非小程序）用途不在本次修改范围内。

明确不做：不删除视频详情页与页面注册、不删除播放请求、不改素材同步。

## 已知风险与合规边界

- 开关只让审核员在界面上看不到视频入口，**不改变**「个人主体未开放视频类目」这一判定。若审核通过后长期开启，仍可能被抽查、举报或后续版本审核时驳回，最坏情况是下架/封禁；根治方式是转为具备资质的企业主体并申请对应类目。
- 提审版本代码包内仍包含播放器组件、视频详情页注册与播放地址请求，若审核方按代码包或旧路径检查，仍可能再次驳回。
- 公众号卡片方案（`2026-10-27-manual-official-video-cards-design.md`）已暂停，不作为本轮实施方案。

## 主要影响范围

- 小程序：`app.config.ts` 页面注册；`app.tsx` 认证放行；登录页；新增协议页与视图组件；个人页；课堂页；视频详情页；问答页；`store/features.ts`。
- 后端和数据库：无改动（开关字段已存在）。
- 平台配置：微信后台《小程序用户隐私保护指引》；提审服务内容说明。
