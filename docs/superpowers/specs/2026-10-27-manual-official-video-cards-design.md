# 手动维护公众号视频卡片设计

日期：2026-10-27

状态：已暂停（2026-10-27）。用户最终决定保留小程序内视频播放与现有 updatedb 素材链路，改用后端开关隐藏视频入口（见 `2026-10-27-miniprogram-review-remediation-design.md` 修复二）。本文保留作为后续备选方案，未实施。

## 目标与已确认事实

用户已决定放弃通过受限的公众号发表接口自动采集链接，改为手动录入。保留小程序课堂的视频栏目及原有 Organic 卡片风格，卡片点击后通过微信官方接口打开已发表的公众号页面。

- 服务器实际调用 `updatedb` 的 `batch_get_published()` 返回 `48001 api unauthorized`。
- `updatedb` 同步视频素材，且草稿同步会清理不在草稿箱的文章；手动入口不能交给这些同步逻辑维护。
- 已确认首条内容标题为“袋鼠式护理（本科室）”，文章链接为 `https://mp.weixin.qq.com/s/ZZo7Wlyjx-vHjOS6aVvFEw`。
- 对外名称为“萌芽护航”，运营者对外称谓为“萌芽护航团队”。
- 现有 `webend` 为展示页，没有可复用的内容管理后台。
- 既有验证码接口会将验证码返回给调用方，不能直接把当前手机号登录当作新增管理员功能的安全基础。
- 现有独立跳转测试项目出现缺少 `@swc/runtime/_type_of.js` 的编译运行错误，尚无有效的手机跳转成功证据。

## 实现路径比较与推荐

1. **1Panel 维护外置 JSON 文件，后端读取，小程序动态展示：推荐第一版采用。** 复用已有服务器、1Panel、Flask 与 Taro 列表和组件，无需新增管理账号、数据库表或公网写接口。适合当前少量内容；操作者需要按 JSON 格式维护。
2. 小程序新增管理员录入页：手机操作方便，但需额外补管理员身份验证及增删改接口，必须同时解决现有登录方式用于管理权限时的风险。适合内容量和维护人数增长后建设。
3. 前端写死链接：每次改内容都要重新构建发布，不满足后续维护需求，不采用。

用户已选择“手动录入”，录入位置采用 1Panel 是本方案的建议，尚未当作用户已确认的偏好。未来升级管理界面时保持用户端接口不变。

## 内容维护方式

在服务器项目目录之外保存配置目录，默认部署路径为 `/root/docker/pinf-content`，文件为 `official-videos.json`。在 1Panel 文件编辑器中录入和修改；部署包提供范例及校验命令。

```json
{
  "version": 1,
  "items": [
    {
      "id": "kangaroo-care",
      "title": "袋鼠式护理（本科室）",
      "articleUrl": "https://mp.weixin.qq.com/s/ZZo7Wlyjx-vHjOS6aVvFEw",
      "coverUrl": "",
      "description": "在公众号观看",
      "enabled": true
    }
  ]
}
```

字段约定：

- `version` 固定为整数 `1`，表示文件格式版本。
- `items` 为数组，最多 200 条；文件最大 1 MiB。数组顺序即展示顺序。
- `id` 必填且唯一，使用 1–64 位小写英文字母、数字、短横线或下划线；后续编辑不改变已有 ID。
- `title` 为去除首尾空白后 1–200 字符的文本。
- `articleUrl` 必填，去除首尾空白后不超过 2000 字符。仅接受 HTTPS、精确主机 `mp.weixin.qq.com`、无用户信息及自定义端口的 `/s/<文章标识>` 或带查询参数的 `/s` 地址；拒绝素材页、播放器地址及带 `tempkey` 或 `is_temp_url` 参数的临时链接。仅做格式检查，不声称已验证文章发表状态；不向服务器发起抓取请求。
- `coverUrl` 可省略或为空；非空时为不超过 2000 字符的 HTTPS 地址，无用户名、密码或自定义端口。
- `description` 可省略，最长 500 字符。
- `enabled` 可省略，默认 `false`；提供时必须为真正的布尔值。设置为 `false` 表示下架，不必删除记录。
- 拒绝重复 ID、相同完整文章地址及未知字段，避免误拼字段静默生效。无法识别同一文章的所有不同分享地址，不承诺语义去重。
- 文章 URL 的签名、查询参数和片段不改写；不把链接改造成 MP4 地址。

首版只初始化已提供发表链接的一条卡片。其余素材在获得各自真实发表链接后再录入，不共用这篇文章地址。

## 后端读取与接口

- 新增独立配置读取模块，路径由 `OFFICIAL_VIDEO_CONFIG_PATH` 控制。请求参数不能指定文件路径。
- 每次请求读取文件；对最多 200 条的小目录不沿用现有 1 小时缓存。只有完整读取且整体校验通过后，才替换进程内最近有效版本。根据规范化后的全部记录计算 SHA-256 `revision`，识别翻页期间目录变化。
- 修改后下一次进入/返回课堂或下拉刷新生效，无需重启后端或重新发布小程序。
- 文件损坏、半写入、路径不存在时，已有最近有效版本则继续返回该版本并记录错误；首次加载或进程重启后无有效版本时返回 503，不把故障冒充为零条内容。
- 新接口 `GET /api/content/official-videos`，沿用现有 JWT 登录校验。支持 `page`、`per_page`、`search`，只返回 `enabled=true` 的记录，保留数组顺序，搜索标题及简介。
- 分页边界沿用现有接口：默认 `page=1`、`per_page=10`，每页最多 50 条。响应沿用 `status/data/pagination` 结构，增加 `revision`，并设置 `Cache-Control: no-store`。
- 不新增 Web 写接口或管理员身份，不修改 `videos`、`articles` 表，不触发 `updatedb`、微信发表 API 或播放地址解析。
- 本地校验命令为 `uv run python -m utils.official_video_catalog --check <文件路径>`，成功返回退出码 0 和内容数量，校验失败返回非零退出码及字段位置，不修改文件。

## 小程序卡片与点击

- 视频栏目改用新列表接口；搜索、分页和下拉刷新都使用同一数据源。
- 首次加载、返回课堂、搜索和下拉刷新替换列表；翻页时若 `revision` 已变化则重新加载第一页，避免新旧目录拼接。相同版本翻页按 ID 去重，不把请求异常当作空页覆盖有效内容。
- 复用 `OrganicCard`、`OrganicBackground`、既有列表排版、主题和 `Feedback.notify`。
- 卡片显示封面、标题、简介及“在公众号观看”；封面为空或加载失败使用既有占位样式。
- 点击直接调用原生 `wx.openOfficialAccountArticle`，URL 在列表加载时已经取得，点击处理内不先请求网络或等待其他异步操作。
- 小程序工程基础库配置设为 `3.17.3`，接口最低支持要求为 `3.4.8`；接口不存在时提示“当前微信版本不支持打开公众号内容，请更新微信”。
- 用户取消不报错；调用失败提示“暂时无法打开公众号内容，请稍后重试”。成功回调不作为页面加载、播放成功或审核通过的证据。
- 解除并移除小程序内视频详情播放器及其页面注册、播放地址请求。后台开关失败或启用旧视频开关时，不能恢复内置播放。
- 不因第三方页面中的播放、点赞等行为自动标记任何护理任务已完成。

## 部署与回退

- Compose 挂载**整个目录**，而不是单个文件，以支持 1Panel 编辑器原子替换文件后立即读到新内容。
- 建议挂载 `${PINF_CONTENT_DIR:-../pinf-content}:/app/content-config:ro`，容器设置 `OFFICIAL_VIDEO_CONFIG_PATH=/app/content-config/official-videos.json`。默认服务器仓库路径 `/root/docker/pinf` 对应外置目录 `/root/docker/pinf-content`。
- 提供范例 `deploy/official-videos.example.json`。首次部署由操作者复制到外置目录并执行只读校验，之后再更新后端容器和小程序。
- 配置在 Git 仓库和镜像之外，后续代码部署不覆盖手动维护内容。
- 修改前保留有效配置备份。误改后恢复备份并校验；有效版本恢复后，下次请求直接生效。
- 未设置封面也能上线，补充封面时需核对微信图片访问条件；不为了封面新增上传或相册权限。

## 范围与验收

本设计仅替代旧审核修复方案的第二项。协议与隐私修复仍是独立任务，不在本方案实施时捎带改造登录系统。

验收必须包括：JSON 错误不覆盖有效内容；下架下一次刷新即生效；`updatedb` 同步不影响手动卡片；所有入口只打开已配置公众号页面；无小程序内播放器或 MP4 解析请求；手机端实际完成页面打开、播放和返回。

调整为外链入口不等同于已满足个人主体服务类目要求，提审须如实说明变化，以平台复审为准。
